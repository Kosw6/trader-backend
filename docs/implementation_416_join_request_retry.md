# 416: 그룹 가입 요청 승인·거절의 중복 실패 안내 수정

2026-10-20 사용자 보고: 오너가 승인/거절하면 실패 알림이 뜨지만 요청자는 새로고침 후 합류한 상태였다.
사용자가 검증 후 AWS 프론트·백엔드 반영을 명시 승인했다.

## 확인된 원인

- 운영 Nginx 기록에서14:44:14 KST 동일 가입 요청 ID의 PATCH가 성공204 뒤
  같은 초에404로 다시 처리된 것을 읽기 확인했다. 이어 동일 경로404가 반복됐다.
  요청 ID/사용자/그룹 식별자와 원문 메시지는 반환하지 않고 동일 여부만 기록했다.
- 첫 요청의 승인은 커밋되었지만 기존 조회는 PENDING 상태에만 잠금을 걸었다.
  같은 요청이 다시 오면 `JOIN_REQUEST_NOT_FOUND`로 실패하는 구조였다.
- 프론트는 React state로만 중복을 막았으며 알림 ID/상세 모달의 요청 ID를 서로 다른 키로 사용했다.
  성공한 알림에도 승인·거절 버튼이 남아 있었고 성공 안내도 없었다.
- 알림 DTO의 boolean `isRead`는 실제 Jackson JSON에서 `read`로 직렬화된다.
  프론트가 `isRead`만 읽어 새로고침 후 처리된 알림을 미처리로 표시하는 문제도 확인했다.
- 중복 HTTP 전송 자체는 확인했으나 첫 중복이 더블클릭/브라우저 재전송 중 무엇인지는 확정하지 않았다.
  사용자 조작 탓으로 단정하거나204가 JSON 파싱 오류라고 추정하지 않았다.

## 수정

### 프론트

- `joinRequestActions.js`의 동기 Set gate를 useRef에 보존한다.
  숫자/문자열 요청 ID를 동일 키로 정규화하여 알림·그룹 모달이 같은 gate를 공유한다.
  진행 중 요청과 이미 성공한 요청은 같은 페이지에서 다시 전송하지 않는다.
- 실제 빈204 응답을 성공으로 처리하고 관련 알림을 모두 읽음·결정 완료로 갱신한다.
  대기 목록에서 제거하고 완료 버튼을 숨기며 승인/거절 성공 안내를 표시한다.
- JSON의 `read`/`isRead` 두 계약을 모두 지원한다. 과거 알림에서 결정 종류가 없으면
  승인을 추정하지 않고 `처리된 요청`으로 표시한다.
- 목록·멤버 새로고침 실패와 실제 결정 실패를 구분한다. 통신 결과 미확인은
  이미 처리되었을 가능성을 안내하며 성공/실패를 단정하거나 자동 재전송하지 않는다.
- 이미 처리한 요청을 늦게 도착한 대기 목록 응답이 되살리지 않도록 필터링한다.

### 백엔드

- `findWithTeamAndRequesterForUpdate`가 종료 상태를 포함해 요청 행을 잠근다.
  기존 트랜잭션 안에서 오너 권한을 검사한 뒤 상태를 판단한다.
- 동일한 승인/거절의 반복은204 no-op이다. 멤버나 알림을 다시 만들지 않는다.
  승인 후 탈퇴한 멤버를 늦은 재요청으로 재가입시키지 않는다.
- 반대 결정으로의 변경은409 `JOIN_REQUEST_ALREADY_PROCESSED`로 거절한다.
  null/PENDING은400, 없는 요청은404, 권한 없는 호출은 기존 권한 실패를 유지한다.
  모든 오류를 성공으로 숨기거나 권한 검사를 건너뛰지 않는다.
- Controller 성공204 및 DTO/URL은 그대로다. DB 스키마·기존 그룹 데이터 변경은 없다.

## 검증

- 프론트 전체235/235, 신규11개 통과. 승인·거절별204, 같은 tick/다른 화면의 중복,
  서로 다른 요청의 독립성, 실패 후 명시 재시도, 잘못된 ID/응답, read 호환,
  관련 알림만 갱신, 불확실한 결과 안내, 화면 연결을 확인했다. Vite 빌드 성공.
- 백엔드 선택64/64, 실패0/skip0. 새13개는 동일 결정 no-op, 반대 결정 충돌,
  완료 요청의 오너 권한 재검사, 탈퇴 후 재가입 방지, 잘못된 상태/미존재,
  잠금·트랜잭션 선언 및 실제 컨트롤러 MockMvc의 반복204/반대409, JSON read 계약을 확인했다.
  기존 그룹 서비스12개/도메인12개와 인증·AI 가용성·노트·차트27개도 통과했다.
- 기존 가입 테스트4개는 현재 요청 ID 기반 API와 명시 APPROVED/REJECTED 인자로 맞췄다.
  PENDING을 승인으로 보내던 이전 mock 설정을 유지한 채 통과했다고 주장하지 않았다.
- 실제 PostgreSQL 동시 트랜잭션이나 브라우저 연속 클릭을 별도 새 테스트 그룹으로 실행한 것은 아니다.
  단위·MockMvc 및 잠금 계약 검사와 운영 반영 후 읽기/잘못된 입력 검사를 구분한다.
- 운영 가입 요청·멤버십·알림을 시험 승인/거절하거나 새 계정/그룹으로 바꾸지 않았다.
